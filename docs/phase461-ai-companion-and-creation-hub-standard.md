# Phase 461 — ScrollVerse AI Companion & Creation Hub Standard

**Purpose:** Define an original ScrollVerse companion experience that helps visitors learn, create, organize, and choose next steps within the Art Learning Studio, Asset Registry, Knowledge Commons, and Legion pathways.

## Original companion principle

Build original companion roles, language, visual identity, and user journeys. Study public companion patterns for capability comparison, but do not copy external characters, names, scripts, proprietary designs, code, datasets, or branded interaction mechanics.

## Companion roles

| Companion role | Local experience | External boundary |
| --- | --- | --- |
| **Archive Guide** | Helps a visitor identify an asset type, source trail, evidence gap, and next archive record | Does not access private files, verify ownership, or make a provider request |
| **Creation Navigator** | Turns a visitor’s chosen subject, form, and intention into original prompt and project-brief structure | Does not generate through an external model or claim an AI account is connected |
| **Source Pathfinder** | Routes a visitor to the Knowledge Commons, Art Learning sources, and research questions | Does not present a source as a universal conclusion or access private research systems |
| **Release Lens** | Explains the difference between research, public display, owner release, commercial preparation, and collector readiness | Does not list, price, mint, pay, publish, or create a provider-side release |
| **Legion Directory** | Maps original ScrollVerse companion roles and public AI-tool discovery pathways | Does not impersonate, synchronize with, or integrate an external AI system |

## Data and privacy boundaries

The local Companion Hub should keep prompts, draft briefs, and visitor selections in the browser unless an explicitly approved data model is added later. It must not state or imply that it reads a visitor’s device, browser history, accounts, private messages, photos, files, microphone, camera, location, wallet, contacts, or other AI conversations.

## Youth and participation boundary

Young visitors may use free learning and browser-local creative preparation with adult-supported guidance. The Companion Hub does not create youth profiles, direct messages, public submissions, payments, tokens, crypto rewards, wallets, purchases, or real-time calls. Any youth-facing live, social, data, financial, or reward component needs separate safeguarding and release design.

## Voice, video, and real-time boundary

The Hub can describe potential future voice, video, and real-time companion modes, but must label them **requires owner release** until the exact provider, consent model, recording behavior, retention, moderation, cost, and data handling are defined. A browser UI must not show a fake live call or pretend a companion is visually or audibly connected when it is not.

## External AI discovery and integration readiness

Tool cards should name their public destination, use category, access label, and provider-boundary note. An integration becomes eligible for review only after the provider, access method, data sent, data received, user consent, account ownership, pricing, model behavior, failure handling, and support path are documented. Visitor choice to open a public external tool is not an integration.

## Quality standard

Show clear local-only labels, original role names, source links, and visible provider boundaries. Offer useful browser-local navigation and preparation tools now; reserve any real-time, account-linked, multimodal, payment, provider, or cross-platform behavior for a separate exact release record.
