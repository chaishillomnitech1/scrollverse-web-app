## 1. The Empire at a Glance

ScrollVerse is a creator-owned portal that brings together identity, culture, music, fashion, learning, sacred archives, creator operations, community, and systems research under one navigable domain. The portal does not depend on a single external platform to explain the work. Instead, its first-party routes hold the primary record, while creator-selected external destinations remain optional handoffs.

The system is organized around a clear operating principle: **a route can be live without claiming that every commercial, legal, custody, partner, chain, or payout outcome behind it is activated.** This distinction protects the real work already built while preserving a deliberate path for later activation.

| Operating state | Meaning in ScrollVerse | Representative paths |
|---|---|---|
| **First-party live** | A ScrollVerse page, database-backed record, document, or navigation experience is implemented in the current project. | [Home](https://scrollverse.co/), [Journey](https://scrollverse.co/journey), [Systems Map](https://scrollverse.co/systems-map) |
| **Protected** | A workflow exists but requires an authenticated owner or authorized administrator session. | [Creator Operations](https://scrollverse.co/creator-operations), [Fashion Review](https://scrollverse.co/admin/fashion-review) |
| **External handoff** | A destination is supplied by the creator or controlled by a third-party platform. | Spotify, Instagram, VEVO, Junior Movies YouTube |
| **Evidence-required** | A readiness route or proposal exists; activation requires source, rights, policy, provider, and/or review evidence. | [Manufacturing Readiness](https://scrollverse.co/manufacturing-readiness), [Impact Incentive Readiness](https://scrollverse.co/impact-incentive-readiness) |
| **Research / proposal** | A documented direction informs future work but does not represent deployment, authorization, or outcome. | [GitHub Operations](https://scrollverse.co/github-ops), [Evidence Standards](https://scrollverse.co/evidence-standards) |

### The Operating Loop

The ScrollVerse operating loop is now standardized as **Source → Review → Test → Decide**. First-party GitHub material and submitted architecture notes can inform a build, but the source record is not itself production proof. A release decision stays human-controlled and separate from research, code, or a scheduled reminder.

| Step | What it means | Result |
|---|---|---|
| **Source** | Record the specific first-party repository, artifact, or creator-supplied material. | Traceable origin. |
| **Review** | Check purpose, provenance, dependencies, rights, and intended scope. | Visible conditions and boundaries. |
| **Test** | Add reproducible automated checks and, where relevant, performance, gas, or security evidence. | Evidence rather than assumption. |
| **Decide** | Make a distinct owner-controlled release decision. | No autonomous activation. |

## 11. Infrastructure and Integrations

The current portal is a React, Express, tRPC, Drizzle, and database application with dedicated routing, protected procedures, object-storage helpers, scheduled review handlers, and deployment checkpoints. Its integration pattern favors a creator-owned data and navigation center, with third-party destinations used as controlled handoffs rather than as the sole record of the work.

| Integration or infrastructure | Current role | Boundary |
|---|---|---|
| **GitHub** | First-party source control, portfolio lineage, and release synchronization. | A repository is a source and implementation record, not automatic authorization to run unreviewed code. |
| **Stripe** | Test-mode payment integration and controlled payment workflows. | Live mode requires separate owner activation and verified product/service conditions. |
| **SendGrid** | Owner and customer notification capability. | Messages do not establish a payment, approval, or legal decision. |
| **S3-compatible storage** | Protected release-asset references and upload support. | Assets remain under authenticated workflow controls. |
| **Daily Revenue Operations digest** | 14:00 UTC owner-facing review reminder. | Summarizes readiness records only; it cannot initiate charges, payouts, tokens, provider changes, or deployments. |
| **PWA and mobile shell** | Installable web experience and mobile-first navigation. | Native-store publication remains a separate release-preparation path. |
