# Phase 463 — Initial ScrollVerse Portfolio Capability Map

**Purpose:** Give visitors a clear route from ScrollVerse to publicly visible source material, original learning pathways, and compatible tool discovery—without treating a public source as a live integration, account connection, deployment, payment method, or commercial result.

## Public source cards

| Source card | Public destination | What a visitor can inspect | ScrollVerse connection | Boundary |
| --- | --- | --- | --- | --- |
| **Chais Hill public GitHub profile** | [github.com/chaishillomnitech1][1] | Public profile, visible repository directory, public links, and profile README | Portfolio starting point and public-code/source discovery | The public profile does not grant private repository access, account control, deployment rights, or permission to run repository instructions. |
| **ScrollVerse Omni Manifesto** | [Public source index and release boundary][2] | Public source index, contribution route, release boundary, and MIT license for that repository’s original curation | Knowledge Commons, Artifact Evidence & Readiness, and Companion Source Pathfinder | Linked repositories retain their own licenses and terms; the index does not create a product, token, payment, contract, or integration. |
| **ScrollVerse portal** | [scrollverse.co][3] | Public portal destination and its separately published routes | Visitor gateway for local-record pathways once managed publication succeeds | Local routes are not live merely because they exist in the workspace. |
| **Spotify artist destination** | [Chais Hill Spotify artist profile][4] | Public artist destination as presented in the GitHub profile | Direct-to-Fan Catalog and Catalog Production Desk context | A public artist page does not establish ownership, master rights, current releases, payout, or a direct sales path. |
| **Art Learning & Practice Studio** | Local `/art-learning-studio` route | Free source links, browser-local prompts, AI discovery cards, adult-supported youth guidance | Creation Navigator and Source Pathfinder companion roles | Browser-local preparation does not create an AI account, provider integration, traffic-revenue path, or external submission. |
| **Asset Registry** | Local `/asset-registry` route | Stable asset families, source state, display state, and release-pathway structure | Archive Guide and Release Lens companion roles | A registry item does not become a listing, sale, token, coin, payment, or payout without its individual release record. |

## Capability categories visible to visitors

| Category | Source-directed capability | Visitor choice |
| --- | --- | --- |
| **Archive and provenance** | Learn how physical and digital assets receive IDs, source context, evidence, correction paths, and display states | Explore the Art Museum and Asset Registry |
| **Original creation** | Use local project briefs, source trails, and original prompts to plan art, music, books, software, or visual work | Start in the Art Learning Studio or Creation Station |
| **Source-led learning** | Follow public research, historical collections, gnostic/manuscript pathways, philosophy, and art sources | Enter the Knowledge Commons and Source Study Library |
| **Release preparation** | Study the path from research to owner release, public display, paid edition, or collector readiness | Open the Product Release Pipeline and Activation Register |
| **Public portfolio discovery** | Inspect public repositories and public documentation at their origin | Open the public GitHub and Omni Manifesto sources |

## Original companion use

The Companion Hub can use this map to make an original recommendation such as: “Choose whether you want to **study**, **create**, **archive**, **prepare a release**, or **inspect a public source**.” It should never claim an external AI can see the portfolio, retain a visitor’s work, access a repository, perform a deployment, or sync an account simply because a public URL is shown.
