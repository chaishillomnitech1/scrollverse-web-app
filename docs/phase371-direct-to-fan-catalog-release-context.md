## Item-level release ledger standard

| Required field | Why it is required before activation |
|---|---|
| Exact item title and version | Distinguishes a master, mix, edit, book edition, visual, look, or bundle from similarly named material. |
| Asset source and preservation master | Connects the product to the exact audio, manuscript, image, or media file that may be delivered. |
| Owner release instruction | Establishes that the owner approves this specific item, at this time, for this exact direct-to-fan use. |
| Master and publishing context | Records the owner-stated right, any known writers/producers/contributors, and any source document or gap. |
| Distribution context | Identifies the destination, service, contract summary, and any exclusivity, takedown, territory, or delivery limitation that applies. |
| Price and package decision | Records an owner-approved price, currency, availability window, incentive, and what the supporter receives. |
| Fulfillment and customer support path | Identifies the exact authorized download, shipment, access, or follow-up delivery process. |
| Optional token record | Requires separate approved metadata, contract, destination, wallet/collection context, and explicit owner release. |

## Direct-to-fan release boundary

The ScrollVerse catalog can act as the owner-controlled front door for approved work. It does not infer an item is sale-ready merely because a catalog, repository, public platform page, or distribution relationship exists. No price, discount, bundle, checkout, digital-delivery key, shipping offer, token, wallet connection, or payment request is created from this context record.

## Correction path

The owner can approve a product one item at a time by providing the exact title/version, asset path, owner-release instruction, source-backed master/publishing and contributor context, approved price/package, fulfillment method, and any distribution limitation. Once those fields are recorded, ScrollVerse can add a direct-to-fan listing, then a separately confirmed test-mode checkout flow, before any production payment action.
