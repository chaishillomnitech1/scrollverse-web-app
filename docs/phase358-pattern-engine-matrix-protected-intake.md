## Retained structural lesson

The supplied seven-field per-asset pattern is compatible with the existing ScrollVerse evidence-first workflow when presented as a **release-readiness checklist** rather than a claim of an immutable or external registry. The useful fields are organized below.

| Record field | Compatible local use | Current evidence boundary |
| --- | --- | --- |
| Source and version | Capture original URL or file reference, capture date, and project/doc version. | A local record is not a public-chain, legal, or external registry receipt. |
| Contributor and rights context | Identify artist, producer, photographer, collaborator, or source credit and the release permission needed. | A visible credit does not replace a rights grant or contributor agreement. |
| Accessible materials | Record caption, transcript, alt text, readable page, audio description, and alternate-format status. | Accessibility status must be checked against the delivered asset rather than asserted globally. |
| Destination | Identify an authorized public page, private archive, distributor, store, or release target. | A named destination is not evidence that a provider, platform, or release is active. |
| Operating state | Use direct labels: **available now**, **research**, or **requires owner release**. | A label does not replace a completed external outcome. |
| Correction path | Keep a source correction, update, removal, or contributor-contact route. | Corrections remain a local process until an authorized external record is updated. |
| Owner release | Record the authorized release decision for each specific asset and destination. | A general instruction does not substitute for a rights-specific release packet. |

## Correction path

An owner or contributor can add a source URL, correct a title/credit, attach a rights record, change a destination, or request a removal through the portal’s source-correction path. A release state is updated only after the corresponding record and authorized destination are available.
