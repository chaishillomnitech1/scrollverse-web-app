# Phase 464 — ScrollVerse Companion Original-Innovation Benchmark

**Purpose:** Turn publicly documented AI-governance and accessibility lessons into original ScrollVerse Companion Hub standards. The benchmarks are design targets and review criteria; they are not claims that the portal currently meets a certification, latency, or external-provider performance level.

## Verified reference lessons

NIST describes the AI Risk Management Framework as a voluntary framework intended to help organizations incorporate trustworthiness considerations into the design, development, use, and evaluation of AI products, services, and systems.[1] W3C states that WCAG applies to dynamic content, multimedia, mobile web, and AI web interfaces, and presents the four accessibility principles of perceivable, operable, understandable, and robust.[2]

These references support a ScrollVerse design choice: local companion experiences should name their role, tell a visitor what happens locally versus externally, give a correction/exit path, and remain accessible without pretending that an external provider is connected.

## Original benchmark scorecard

| Benchmark | Original success criterion | Current design consequence |
| --- | --- | --- |
| **Role clarity** | Every companion card states one role, one useful local task, and one clear next path | Archive Guide, Creation Navigator, Source Pathfinder, Release Lens, and Legion Directory remain distinct |
| **Local usefulness** | A visitor can create a useful project brief, source list, asset record, or learning path without an external account | Browser-local prompt, asset, and artist-support preparation controls are primary |
| **Source clarity** | Every external destination card carries source name, public URL, access label, scope note, and correction path | Public GitHub, tool, collection, and AI discovery cards do not become integrations by implication |
| **Accessible participation** | Companion routes are designed for keyboard navigation, readable contrast, descriptive controls, and adult-supported youth learning | Accessibility review is required before public release; this is not a claim of current WCAG conformance |
| **Consent-first handoff** | Before a visitor leaves the local portal for an external tool, the UI states that the provider controls the next account, terms, data, cost, and output path | A public external link is labeled a visitor choice, not an account connection or data sync |
| **Correction-capable creation** | Every saved local template can be reset, revised, or redirected without a hidden external action | Local briefs and records remain browser-local unless an explicit future release changes the scope |
| **Multimodal honesty** | Voice, video, live calls, and camera/microphone modes are displayed only when a real, consented capability exists | No simulated live companion call, fake camera state, or implied real-time agent is shown |

## Innovation principle

The benchmark is not to duplicate another company’s companion identity or claim a universal superiority. The original ScrollVerse advantage should come from combining **creative preparation**, **source transparency**, **asset stewardship**, **visitor choice**, **local-first controls**, and **release readiness** in one connected experience.

## External-access gate

Any future external model, real-time voice/video, account connection, browser permission, user-data handoff, analytics event, or payment feature needs its own provider, consent, privacy, youth, cost, retention, failure-handling, and owner-release record. A benchmark does not authorize an integration.
