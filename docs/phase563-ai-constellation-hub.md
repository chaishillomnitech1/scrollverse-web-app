# Phase 563 — AI Constellation Hub

**Purpose:** Create a unified ScrollVerse entry point for original AI roles, compatible public AI discovery, and provider-integration readiness.  
**Operating state:** **browser-local discovery and tutorial planning**.

## Constellation taxonomy

The hub separates three different types of AI pathway so visitors can understand what is available locally, what is a public outbound discovery link, and what would require a verified provider connection.

| Constellation layer | What it contains | Operating state |
|---|---|---|
| ScrollVerse AI roles | The original AI Legion Apex role registry, Council mode, specialist profiles, and creator-directed role guidance | Available now as browser-local ScrollVerse experiences |
| Public AI discovery | Clearly labeled outbound links to well-known public AI entry points for research, work, and creative exploration | Available now as external discovery links; each provider’s own terms and controls apply |
| Provider integration readiness | A consistent record for a verified provider, intended data flow, required permissions, owner, scope, privacy, cost/terms review, and exact action | Requires owner release; no connection is represented as active until this record is complete |

## Tutorial standard

Each original ScrollVerse AI role receives a concise tutorial path that explains **what the role helps with**, **how to use it responsibly**, **the source and limits of the role**, **a practice prompt**, and **the exact route to open next**. Future public video generation requires an original script, visual direction, caption file, narrator guidance, accessibility plan, media-use record, destination, and explicit owner release. The hub can host the browser-local tutorial experience now without asserting that a video has been generated or published.

## Provider boundary

The directory may point to public provider home pages, but a link does not create a partnership, endorsement, API integration, account connection, shared data flow, cross-system agency, or provider-controlled action. Any actual integration must be reviewed lane-by-lane for its data, privacy, cost, rights, provider terms, intended result, and owner confirmation.

## State-of-the-art interaction standard

The hub uses role filters, capability filters, direct purpose labels, accessible text-first tutorials, mobile-responsive controls, related-route handoffs, and a copyable integration brief. This makes the portal useful even before any external provider is connected.

## Evidence-completion standard

Every AI-facing capability must end in a visible operating state rather than an empty assertion. The hub records each capability as **available now** when it works browser-locally; **research** when it has source context but no verified operation; or **requires owner release** when a provider connection, account, data flow, or external outcome is proposed.

| Capability type | Evidence required to move beyond research | Outcome once complete |
|---|---|---|
| Original ScrollVerse role | Purpose, limits, related route, tutorial copy, and accessible interaction pattern | Browser-local role available now |
| Public AI discovery link | Official public entry point, link label, and a no-partnership/no-integration boundary | External discovery link available now |
| Tutorial video | Original script, visual treatment, captions, narrator direction, accessibility plan, destination, and owner release | Production-ready tutorial packet |
| Provider integration | Provider, intended data flow, account/permission owner, scope, privacy/terms review, cost review, test evidence, exact action, and owner confirmation | Verified integration record; the external action remains separate |
| Technical or quantum claim | Named platform, reproducible method/code, execution date/ID, output, and reviewable source trail | Source-backed technical result |
